MCP: using QuakeC Studio from another agent

quakec-ide mcp serves the agent's tools over the Model Context Protocol, so Claude Code or any other MCP client can build, test, play and edit your mod with the IDE's own commands. It is the same set of tools the built-in agent has, and no more. docs/mcp.md is the full reference.

With Claude Code

claude mcp add quakec -- quakec-ide mcp /path/to/your/mod

Add --scope project to share it with everyone who opens the repository; Claude Code then writes it to the repository's .mcp.json. Add --dialect fteqcc for an FTEQCC mod with no quakec.toml, and --game <folder> when the game is not where quakec-ide finds it.

With another client

A client that starts a stdio server takes the same command:

{
  "mcpServers": {
    "quakec": {
      "command": "quakec-ide",
      "args": ["mcp", "/path/to/your/mod"]
    }
  }
}

Working in the open window

With --connect, the tools run in the QuakeC Studio window you have open instead of a session of the server's own. An edit the agent stages then shows in the window's Proposed changes, a build is the window's build, and a game it plays is the window's game. Open the app with the project first.

claude mcp add quakec -- quakec-ide mcp /path/to/your/mod --connect

What it may touch

The tools read and write only under the project, plus each --read and --write folder. --read-only lets nothing build, edit or play.

A change to the code made with edit.stage_change is staged, as the built-in agent's are, and reaches disk only when it is accepted and saved. A map tool's edit is made at once, with no review waiting for you: edit.undo, or restoring a checkpoint, takes it back.

What it can do

Every command of the IDE is a tool, so an agent can do anything the palette can. The commands reference lists them all. A few to know:

  • project.reference: what to read before writing QuakeC, by topic: quakec, entities, monsters, models, maps and workflow. The server's instructions send an agent there first.
  • project.compile, project.test, preview.play and engine.screenshot: build, test, play, and look at a frame of the game, which runs with no window unless the server is connected to your app.
  • map.generate, map.build_room and map.build_passage: a whole random level, or one room of a shape from id's levels and the passage between two (Rooms and passages).
  • model.*: read a model, change its skin, size and frames, or import one (Models).
