The agent

The agent, in the right panel, changes your project to do a task you give it in words, and does not call the task done until the project compiles clean and its tests pass. It uses the same commands you do, so you can watch what it does, and nothing it changes is written until you accept it.

The agent runs on a model provider you choose, or the panel runs Claude Code or another outside agent for you. QuakeC Studio has no account and no model of its own, and it sends nothing anywhere until you set one up (Privacy).

Set up a provider

Until a provider or an outside agent is set up, the Agent section says The agent is not set up yet. It offers Use Claude Code (below), then, under Or use a model provider:, its form:

  • Anthropic, with an API key from the Anthropic Console;
  • OpenAI-compatible, for OpenAI or any service with the same API, with its Address (optional) and an API key;
  • Ollama (local), a model running on your own computer, which needs no key and keeps everything on it.

Fill in the Model and the key, and press Save. The key is kept in the system keychain, never in a file; the rest goes to agent.json in the app's data directory. Settings opens the form again later.

Use Claude Code or another agent

The panel can run an outside agent over the Agent Client Protocol (ACP) in place of a model provider. If you use Claude Code, it needs no provider or key in the IDE at all.

Press Use Claude Code. It needs Node 22 or later and the claude command, signed in. The IDE adds Claude Code to the agent.external setting (Settings) and runs its ACP adapter with npx at a version the IDE was checked against. To run another agent that speaks ACP, add it to agent.external with its name, command and args. With more than one agent set up, a list beside the threads chooses which one a new thread runs on.

The IDE gives the agent its own tools, the same ones MCP serves, connected to your open window, so its builds, tests and game are the window's. A thread shows what the agent says and its reasoning, each tool call and how it went, and the agent's own permission questions as buttons. Stop ends its turn; a second Stop ends an agent that does not answer.

Claude Code writes your files itself rather than staging its edits, so they do not wait in Proposed changes. The IDE records a checkpoint before every outside agent's thread starts: Restore checkpoint puts the project back as it was.

Give it a task

Type the task in What should the agent do? and press Start. For example:

Make the axe do 200 damage, and add a test that proves it.

Each task is a thread, and several can run at once; the row above the task box switches between them. Before the agent changes anything, the IDE records a checkpoint of the project.

The agent starts with a brief of your project: its AGENTS.md if it has one (write your notes for the agent there), each module's dialect and engine, the engine's builtins, the files, and whether the project compiles and its tests pass now.

While it works, the thread shows what the model writes as it writes it, drawn as Markdown, and each command it calls with whether it ran. When the built-in agent says it is finished, the IDE compiles and runs the tests itself:

  • Done: the compile is clean and every test passes. Its summary follows.
  • Not done: what still fails. The agent is told and goes on, until it runs out of turns.

Review its changes

The agent's edits are not written to your files. They are staged, and Proposed changes lists each change, hunk by hunk, with Accept and Reject, and Accept all and Reject all. Once every hunk of a file is decided, the accepted ones are the editor's text of it, unsaved: save as usual.

Restore checkpoint puts the project back as it was before the thread started.

What it may do

The picker beside Start sets the profile, kept in the project's settings:

  • Ask: the agent only reads the project, the game and the settings.
  • Write (the default): reading and editing run unasked; anything else that changes the project, the game or the settings asks you first.
  • Full: every tool runs unasked.

A call that needs your permission waits in its thread, showing the tool, the paths it names and why it asks, with Allow once, Always allow and Deny. Always allow keeps a rule in the project's settings for exactly what the call named. The agent.tool_permissions setting (Settings) holds rules per tool: allow, ask and deny patterns over the paths a call names, deny winning over ask and ask over allow.

Point it at something

A task can name what the agent should look at, with an @ mention. Each one is read when the thread starts and attached after the task:

Mention What is attached
@file:<path> The file's text, its unsaved edits included; the path is relative to the project
@symbol:<name> Where the name is defined, file and line
@builtin:<name> The engine's declaration of the builtin
@entity The edict selected in Entities, or picked in the paused game, with every field
@error The last error the game's console printed

For example: Why does @symbol:W_FireAxe miss? See @error.

Ask about this

Right-click a row in Entities and choose Ask about this, or press Ask about this in Properties. The IDE selects that edict and starts a thread that explains what it is doing and why: what spawned it, what its think function does next, and anything in its state that looks wrong. The thread holds its classname, its current think function and when it is due, and every field, as the game has them at that moment. The agent is told not to change code unless you ask.

Inline edit

Select some code in the editor and press Cmd+K. A box asks Change the selection to…: say what you want and press Enter. The model rewrites only the selection, and the answer is shown in place as a diff from the text before. Accept keeps it, and one undo still takes it back; Reject puts the text back. Inline edit uses the provider the agent panel has.

What does this code do?

Select some code, right-click it and choose What Does This Code Do?. A thread starts that asks the agent for a plain explanation of those lines, naming their file and lines, and tells it not to change anything.

The command line and other agents

The same agent tools are served to Claude Code and other agents over MCP: see MCP. Among them, project.reference gives any agent the reference the built-in agent reads, on QuakeC, the engine, monsters, models, maps and tests.
