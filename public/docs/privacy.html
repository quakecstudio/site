Privacy

QuakeC Studio works offline, with no account and no telemetry. This page lists every network request the app can make, and when it makes each one. With no model provider set up and no outside agent run, it makes none, and the editor's CI checks that.

The website's own practices, and how to reach us, are in the Privacy Policy.

No account, no telemetry

  • There is no account and no sign-in. Nothing asks for an email address.
  • There is no telemetry, no crash reporting, no analytics and no update check. The log is written to the app's own folder on disk and is never sent anywhere.
  • Projects, settings, checkpoints and recent projects stay on disk. Settings are in settings.toml in the app's config folder and .quakec-studio/settings.toml in a project; checkpoints are git objects in the project.

Every network request

WhenWhat is requested
The agent is asked something (a thread or an inline edit), once a provider is set upThe provider's API: https://api.anthropic.com for Anthropic, the OpenAI-compatible address you entered (https://api.openai.com/v1 by default), or http://localhost:11434/v1 for a local Ollama, which stays on your computer. Each request carries the task, the context of your project the agent was given or read, and the key.
A project is made from a starter (New Project…, or quakec-ide new) without a local copyThe starter's files at their pinned commit from https://raw.githubusercontent.com (id-Software/Quake-Tools for id1, id-Software/quake-rerelease-qc for the rerelease), each checked against its pinned SHA-256. quakec-ide new --from <dir> reads a local copy instead and makes no request.

Nothing else in the app goes over the network:

  • The game, the debugger and the scenarios run on your computer, talking to the IDE over a local socket (a Unix socket, or a named pipe on Windows).
  • The MCP server (quakec-ide mcp) and the language server (quakec-lsp) talk over stdin and stdout, and quakec-ide mcp --connect over the app's own local socket.
  • A model provider's key is kept in the system keychain, never in a file, and is sent only to that provider.
  • A help popup's Read more in the user guide opens that section of this guide in your browser, and only when you click it; the app makes no request itself.

Outside agents

An outside agent the agent panel runs over ACP (Use Claude Code or another agent) is a program of its own, started on your computer, and makes whatever requests it makes. Use Claude Code runs Claude Code's ACP adapter with npx, which downloads it from the npm registry the first time, and Claude Code talks to Anthropic under your own sign-in. QuakeC Studio sends such an agent your task and gives it its tools; it sends nothing to anyone itself.

How it is checked

The editor's CI runs each step in a network namespace with no network, under strace, and fails a step whose trace shows an internet address or a name lookup. With no provider set up, it runs:

  • a control, quakec-ide new id1 with no local copy, which must fail and must show its request, proving the trace sees one;
  • the command line: new from a local copy, build, check, test, and an MCP session;
  • the desktop app: a session that opens a mod and every file in it, builds, checks, runs the tests, searches, opens the command palette and asks for an agent thread, which does not start.

In the recorded run, every step but the control made no network call. The editor's privacy notes have the details.
