QuakeC Studio user guide

QuakeC Studio is an IDE for QuakeC, Quake's game code. It has its own compiler, it runs your mod in the game as you edit, it has a debugger that stops the running game, and it has an agent that can change your code and prove the change works. It runs on macOS, Windows and Linux, offline, with no account.

Read these in order the first time:

  1. Install: the app for macOS, Windows or Linux, and how to update and remove it.
  2. Getting started: from nothing to your own mod running in Quake.
  3. Opening a mod: an existing mod, its progs.src and quakec.toml, and what the IDE shows of it.
  4. The play loop: Play, edit, save, and see the change in the running game.
  5. Debugging: breakpoints, stepping, watches, and the entities of the running game.
  6. The agent: asking the built-in agent, or Claude Code, to do a task, and reviewing what it did.
  7. MCP: giving the same tools to Claude Code or another agent.
  8. The map editor: building a map, compiling it, finding a leak, and playing it from where you stand.

Reference pages:

  • Keys: the keys you will use most, Vim mode, and changing a key.
  • Command line: quakec-ide and the language server, quakec-lsp, for other editors.
  • Settings: every setting.
  • Your Quake game data: where QuakeC Studio finds the game's files.
  • Privacy: every network request the app can make.
  • What's new: what each release changed.
  • FAQ: Quake, cost, platforms, dialects, TrenchBroom and more.
  • Troubleshooting: when something does not work.
  • Commands: every command the palette, the CLI, the agent and MCP share, on GitHub.
  • Keymap: every default key, on GitHub.

Keys are written for macOS. Off macOS, Cmd is Ctrl.
